# D-038: Curriculum upgrade preview

Status: Option B approved by owner, 2026-10-14; fictional/local read-only preview only

Approval does not authorize actual migration, student notices, private progress inspection, Teacher authority, real data or production.

## Question

What should we build before changing the curriculum assigned to existing students?

## Why this needs your decision

F005/F009/F023 deliberately pin published text and files. Publishing a new version never changes an existing student's assignment. DW-011 is deferred. Actual upgrades need decisions about notice, consent, progress, assignments and rollback. Even a staff preview needs explicit scoped authority and a privacy boundary.

## Options

### A — Keep existing students pinned

Defer upgrade tooling. Existing students retain their current versions; publishing new material does not update them automatically. No extra vendor spending or new authority. Reversible later.

### B — Staff-only read-only impact preview (recommended)

Let selected staff with existing content-publication and enrolment-operation authority receive a separate explicit revocable offering-scoped upgrade-preview grant. No automatic Teacher or global-role bypass.

Compare two published versions within the same offering: topic/lesson/material differences and aggregate counts of active enrolments affected through cohorts or direct assignment. No student names, Member IDs, individual records, private checklist/progress, grades, passive analytics, private object URLs or new teacher workspace access.

This preview changes no student assignment, progress, file access or existing assignment/feedback record, sends no student notice, and cannot execute a migration. It supplies evidence for a later explicit upgrade-policy decision. No extra vendor or paid plan for fictional/local implementation; not real-data/production approval. The preview is reversible and read-only.

### C — Define the full cohort/student upgrade policy first

Plan notice/consent, cohort versus individual movement, progress mapping, assignment history, access changes, rollback and approval authority before building tooling. Discovery has no added vendor spending, but more scope and additional policy choices. No student changes or migration implementation until that policy is approved.

## Recommendation

B makes the effect of a newer curriculum visible without inventing migration rules or moving anyone. Choose C if the full upgrade policy must be settled before even a preview.

## What can continue while pending

Existing pinned coursework, file authoring, assignments and alerts remain unchanged. No preview grant, report, student notice or migration is implemented before selection.
