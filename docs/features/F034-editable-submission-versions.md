# F034 Editable unreviewed submissions and repeated attempts

Status: D-049 B approved 2026-10-18; implementation and local acceptance complete, required PR CI pending. Risk Red: private educational files, attribution and concurrent review.

Students may start further numbered attempts while assigned access/release remains active, without a correction request, including after a completed review. One draft per assignment remains. An unreviewed submitted attempt has Edit attempt; this creates a new internal version of the same displayed attempt, retaining its prior submitted snapshot and teacher drafts. Reviewed attempts cannot be edited, including correction-request outcomes.

Implementation uses copy-on-write submission rows and private file references: original submitted rows and bytes are not overwritten. Physical sequence IDs stay unique; logical attempt number and version identify the learner-visible history. Superseded snapshots are omitted from the current review queue and student primary history. Existing scoped access still governs historical records. A teacher must explicitly review updated files before opening a new draft for an edited version; prior private writing is retained in the old snapshot, not silently transferred or published. Old draft publication is rejected server-side after an edit. The owning attempt lock serializes edit versus publication; the winner determines whether editing or publication is permitted. Reviews of older distinct attempts cannot overwrite the newer attempt's assignment summary.

Shared file bytes are retained while referenced. Removing a draft attachment detaches metadata through a trusted owner-checked transaction before any unreferenced byte deletion, so concurrent submission cannot include a deleted object. Retry receipts are private and scoped to the original owner; no extra worker or retention activation. Purge candidate selection protects paths with any non-eligible reference. File limits remain 10 × 10 MB and 50 MB per attempt; free attempts are not a promise of unlimited storage. No new teacher authority, AI provider, grading, production or paid services.

Acceptance: multiple attempts and versions, review-completed/correction locks, one draft, stale teacher publication denial, copied-file removal protection, retries, revoked/ended/withdrawn access, older-review summary isolation, database/Storage/frontend/browser tests and independent security review. Regenerate dated usage handbooks after accepted implementation.

Independent review found and prompted fixes for the existing purge-selection/finalization race (durable file claims now fence finalization) and unfinished-edit closeout history (archive uses the latest finalized snapshot per logical attempt, never the draft). Shared-path safety relies on enforced current write boundaries: browser metadata is read-only, one draft per instance, and trusted edits copy only same-instance submitted snapshots. No new cleanup worker is activated.

Local evidence: 440 app tests, 1,179 database assertions, 78 Chromium journeys, production build/bundle budget and actual SDK/Storage acceptance including competing edit/publication. Independent security review cleared the final implementation. Both printable handbooks regenerated, with all 18 rendered pages inspected. No production activation.
